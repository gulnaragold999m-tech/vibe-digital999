# Подтверждение прав в Яндекс.Вебмастере

## Как сейчас на нашем сайте

Мета-тег в `<head>` файла `public/index.html`:

```html
<meta name="yandex-verification" content="75f670095b8ac749" />
```

Права подтверждены, панель работает. Удалять тег нельзя: без него Вебмастер отключит
доступ, а вместе с ним — переобход страниц, диагностику и отчёты по запросам.

## Новый способ: тег в менеджере тегов

Вебмастер добавил подтверждение через **Яндекс Тег Менеджер** и **Google Tag Manager**.
Код подтверждения вставляют не в разметку сайта, а тегом в менеджере — доступ к
исходному коду страницы не нужен.

Порядок в Яндекс Тег Менеджере:

1. Метрика → Тег Менеджер → «Теги» → **+Тег**.
2. Название тега, шаблон — **Яндекс Вебмастер**.
3. Код подтверждения из кабинета Вебмастера скопировать в поле «Код подтверждения».
4. «Добавить триггер» → тип **«Инициализация»** → название → сохранить.
5. Сохранить тег.
6. **Опубликовать** — кнопка справа сверху, с комментарием к версии. Без публикации
   тега на сайте нет: сохранённый тег и работающий тег — разные вещи.
7. Вебмастер → страница подтверждения прав → «Подтвердить».

Через GTM порядок такой же, он описан в Справке Яндекс Вебмастера.

## Когда какой способ

| Ситуация | Способ |
| --- | --- |
| Свой сайт, доступ к коду есть | мета-тег в `<head>` |
| Клиентский сайт, менеджер тегов уже стоит | тег в менеджере |
| Клиентский сайт на конструкторе, кода не дают | тег в менеджере; если менеджера нет — файл в корень или DNS-запись |
| Менеджера тегов нет и не планируется | не ставить его ради одного подтверждения |

## Чем платим

- **Права держатся на контейнере.** Удалили тег, откатили версию, сняли контейнер
  с сайта — подтверждение слетает. Мета-тег в разметке живёт, пока живёт страница.
- **Публикация — отдельный шаг.** Тег сохранён, но не опубликован — значит, его нет.
- **Лишний внешний скрипт.** Контейнер грузится на каждой странице.
- **Одна точка отказа на два дела.** Сломался менеджер тегов — легли и аналитика,
  и права в панели.

## Почему у нас остаётся мета-тег

Доступ к коду свой, менеджера тегов на сайте нет. Шрифты уже убрали с серверов Google
ради скорости и приватности — тащить внешний контейнер ради одной строки в `<head>`
означает идти обратно. Мета-тег ничего не грузит и работает без JavaScript.

Если менеджер тегов когда-нибудь понадобится под рекламные пиксели, способ можно
поменять. Порядок только такой: сначала подтвердить права новым способом, дождаться
в Вебмастере статуса «Права подтверждены», и лишь потом убирать мета-тег из кода.

## Что это меняет в аудитах клиентов

Раньше отсутствие `yandex-verification` в коде читалось как «Вебмастера, скорее всего,
нет». Теперь так делать нельзя: права могли подтвердить тегом в менеджере, и в разметке
не будет ничего.

Скрипт `.claude/skills/seo-audit-ru/scripts/audit.mjs` это учитывает. Если мета-тега нет,
но на странице стоит менеджер тегов, замечание понижается до незначительного с
формулировкой «проверить в Вебмастере руками». Вывод «прав нет» по одной разметке
больше не делается.

У Google Search Console подтверждение через GTM было и раньше. Работает так же и с той
же оговоркой: пропал контейнер — пропали права.

## Проверка

```bash
curl -s https://vibe-digital999.ru/ | grep yandex-verification
```

Тег должен найтись. Дальше — в Вебмастере на странице подтверждения прав статус
«Права подтверждены». Если меняли способ, смотреть оба пункта до того, как удалять
старый.
