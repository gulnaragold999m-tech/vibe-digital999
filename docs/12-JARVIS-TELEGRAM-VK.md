> **Делаете бота ВК в другом проекте — берите `docs/VK-BOT-CHEKLIST.md`.**
> Там то же самое, но без привязки к этому сайту: настройки ВК, коды
> ошибок, устройство кода, ловушки Amvera и способ проверки. Файл сделан
> переносимым, чтобы его копировали в проекты автошколы и типографии.
> Этот документ — про наш конкретный сайт и про Telegram.

Передача опыта из соседнего проекта **granat-kmv** (сайт и боты типографии
«Гранат»). Там Джарвис работает в двух мессенджерах с 09.08.2026, и все
грабли, перечисленные ниже, собраны живьём, а не придуманы.

**Главное правило: нового Джарвиса не создаём.** Ассистент уже написан,
работает и собирает брифы. Нужна не вторая голова, а вторая дверь.

## 2. Жёсткое ограничение, из-за которого нельзя просто взять токен Джарвиса

**Один токен Telegram-бота = один процесс, который его слушает.**

Если два приложения одновременно вызовут `getUpdates` (long polling) с одним
токеном, Telegram вернёт **409 Conflict**, и работать перестанут оба. То же
с вебхуком: адрес у токена может быть только один.

Токен `@GranatJarvis_bot` уже занят приложением `jarvis-bot` проекта
granat-kmv — оно его слушает постоянно. Поэтому:

- ❌ Нельзя переиспользовать этот токен для опроса в vibe-digital999.
- ✅ Можно и нужно переиспользовать его **для отправки заявок владельцу** —
  это обычный `sendMessage`, он конфликта не вызывает. Так сейчас и сделано
  в `api/lead.js`, и это правильно.

**Рекомендация: завести отдельного бота у @BotFather для vibe-digital999.**
Это НЕ «новый Джарвис»: мозг, промпт и сбор брифа остаются те же самые, из
`api/brief.js`. Новая только дверь — отдельный адрес, куда приходит клиент
digital-направления, и отдельный токен, чтобы два приложения не дрались.

В `.env.example` для этого уже заложена переменная `SITE_NAME` с подписью
«нужна, если бот общий с другим сайтом» — она пригодится, чтобы в заявке
было видно, с какого сайта пришёл человек.

Если всё же хочется один бот на два сайта — это возможно, но тогда опрос
должен жить ровно в одном приложении, а второе получать клиентов от него по
сети. Это дороже в поддержке и ломается целиком, когда падает первое.
На нашем объёме не окупается.

## 3. Telegram: чего ожидать

### 3.1. Telegram в России нестабилен — это норма, а не авария

09.08.2026 он не открывался полдня, и приём заказов в granat-kmv встал.
Именно поэтому там появился ВКонтакте. Здесь ВК уже есть — большое
преимущество, не потеряйте его.

### 3.2. На Amvera не работает IPv6

Самая дорогая грабля. DNS отдаёт для `api.telegram.org` и IPv4, и IPv6.
Если библиотека выберет IPv6 — соединение **висит до таймаута**, и выглядит
это как «Telegram не отвечает».

В granat-kmv это стоило двух падений бота 10.08.2026, второе — насмерть.

В Node это лечится так: при старте приложения задать приоритет IPv4.

```js
const dns = require('node:dns');
dns.setDefaultResultOrder('ipv4first');
```

Ставить в самом начале `server.js`, до первых сетевых вызовов. Node 20 это
поддерживает (в `package.json` уже стоит `"node": ">=20"`). Проверено:
команда есть и работает.

Точность важна: `ipv4first` **ставит IPv4 первым**, а не выкидывает IPv6 из
списка. Обычному клиенту этого хватает — он берёт первый адрес. Если
зависания всё-таки останутся, IPv6 придётся отфильтровать явно, подменив
`dns.lookup`. В granat-kmv на Python пришлось делать именно так: там патчат
`socket.getaddrinfo` и оставляют только IPv4.

### 3.3. Падение Telegram не должно ронять ВКонтакте

В granat-kmv ВК крутится потоком **внутри того же процесса**, что и
Telegram. 10.08.2026 Telegram не ответил при старте, ошибка дошла до верха и
остановила программу — вместе с ней умер ВК, то есть ровно тот канал,
который заведён на случай смерти Telegram.

В Node всё в одном процессе точно так же. Поэтому:

- ошибку запуска Telegram-опроса **ловить и не пробрасывать наверх**;
- при неудаче писать в лог и продолжать работать одним ВК;
- не вызывать `process.exit()` из-за Telegram.

### 3.4. Мелочи, которые сэкономят время

- Голосовые сообщения Bot API **не расшифровывает**. Нужен внешний сервис.
  Из России работает Яндекс SpeechKit; у OpenAI Whisper не выйдет ни
  заплатить, ни достучаться. Быстрое распознавание берёт запись до 30 секунд.
- Отметок «прочитано» у бота нет — не стройте на них логику.
- Возраста пользователя в Bot API нет. Косвенно свежесть аккаунта видна по
  величине `user.id`: чем больше число, тем позже регистрация.
- Бот не может написать первым тому, кто ему не писал.

## 4. ВКонтакте: настройки, без которых бот молчит

Пройдено живьём 11.08.2026 на сообществе `club240607590`. Порядок именно
такой: следующий пункт не появляется в интерфейсе, пока не сделан предыдущий.

1. **Сообщения сообщества** — включить. Без этого бот не получит ничего.
2. Управление → Сообщения → **«Настройки для бота»** → «Возможности
   ботов» в положение «Включены» → **обязательно «Сохранить»**. Без
   сохранения — ошибка **912 «this is a chat bot feature»**.
3. Там же галочка **«Добавить кнопку „Начать“»** → снова «Сохранить».
   Переключатель и галочка сохраняются ОТДЕЛЬНО. Кнопка «Начать»
   заменяет человеку пустое поле ввода: нажал — разговор начался.
   Вторую галочку, «Разрешать добавлять сообщество в чаты», не ставить:
   бот рассчитан на личную переписку, в групповом чате он мешает.
4. **Ключ доступа**: Управление → Работа с API → Ключи доступа →
   Создать ключ. Отметить **две** галочки: «Сообщения сообщества»
   и **«Управление сообществом»**. Второе нужно, чтобы бот сам включал
   Long Poll (см. ниже). Ключ показывается **один раз**.
5. **Long Poll руками включать не нужно** — это делает код при запуске,
   `ensureLongPollSettings` в `api/vk-bot.js`. Признак успеха в логе:
   `[vk-bot] Long Poll включён, подписка на входящие сообщения есть`.

### Почему Long Poll включает код, а не человек

11.08.2026 раздел «Работа с API → Long Poll API» **не нашёлся в интерфейсе
ВК** ни по одному пути: правое меню Управления заканчивается на «Журнал
действий», прямой адрес `vk.ru/club<ID>/settings?act=api` перебрасывает
на «Основную информацию». Полдня ушло на поиски раздела, которого там,
похоже, больше нет.

Метод `groups.setLongPollSettings` делает ровно то же самое одним запросом.
Разовое включение из браузера, если код ещё не выкачен:

    https://api.vk.com/method/groups.setLongPollSettings?v=5.199&group_id=240607590&enabled=1&api_version=5.199&message_new=1&access_token=КЛЮЧ

Ответ `{"response":1}` — включено, настройка остаётся в ВК навсегда.

Порядок параметров в этой ссылке не случайный: `v` первым, `access_token`
последним. Токен длинный, и при копировании обрывается именно хвост —
если `v` стоит в конце, он теряется, и ВК отвечает ошибкой 8 «v is
required». С токеном в конце обрыв даёт понятную ошибку 5 про токен.

### Ошибки ВК, которые встретятся

| Код | Что значит | Что делать |
|---|---|---|
| **901** | Сообществу нельзя писать пользователю первым | Написать сообществу любое сообщение со своей страницы |
| **911** | Слишком много рядов в клавиатуре | ВК держит максимум **10 рядов** и 5 кнопок в ряду. В granat-kmv было 12 категорий — раскладывали по две в ряд, а не резали список |
| **912** | Возможности ботов не включены | См. пункт 2 выше |
| **5** | `User authorization failed` | Ключ отозван — выпустить новый. Но если тот же токен работает в приложении, значит он просто **обрезался при копировании**: брать значение из переменных Amvera, а не из окна ВК |
| **8** | `v is required` | Из адреса потерялся хвост `&v=5.199`. Ставить `v` первым параметром |
| **15** | `Access denied` | У ключа нет права «Управление сообществом» — пересоздать ключ с обеими галочками |
| **27** | Ключ выдан не тому сообществу | Проверить `VK_GROUP_ID` |
| **100** + текст `longpoll for this group is not enabled` | Long Poll выключен | Это НЕ про `peer_id`, хотя код 100 обычно означает кривой параметр. Один код у ВК значит разное — читать текст ошибки, а не только номер |

Коды расшифрованы словами прямо в логах — `VK_ERRORS` в `api/vk.js`.
Подсказка для 100 зависит от текста ошибки: неверная подсказка хуже, чем
никакой, по ней чинят не то место.

### Приятная особенность ВК

ВКонтакте часто **сам расшифровывает голосовые** и кладёт текст в поле
`transcript` объекта `audio_message` (при `transcript_state: "done"`).
Бесплатно и уже готово — брать оттуда до всякого SpeechKit.

## 5. Грабли в разговоре, которые стоили клиентов

Собраны 10.08.2026 на живых проверках granat-kmv. Все — не про код, а про
то, как человек читает бота.

**Согласие только кнопкой — петля без выхода.** Человек написал «нужно 100
визиток срочно», получил приветствие. Написал имя — получил приветствие
снова. И так по кругу: согласие засчитывалось только нажатием кнопки.
Лечение: считать согласием и короткие слова — «да», «хорошо», «согласна»,
а на второй раз слать не то же приветствие, а короткую подсказку.

**Приветствие обещало то, чего бот не делает.** В тексте было «понадобится
ваше имя», хотя во ВК бот имя не спрашивает — берёт из профиля. Человек
прочитал обещание и написал имя. Правило: в приветствии описывать ровно то,
что бот сделает следующим шагом.

**Первая фраза клиента терялась.** Человек приходит не с пустыми руками — он
сразу пишет, что ему нужно. Эту фразу надо запомнить и после согласия
проиграть заново, а не заставлять повторяться.

**Цену считала модель, а не код.** В прайсе, который видит модель, забыли
показать множители — и срочный заказ был оценён в 450 ₽ вместо 585 ₽.
Правило: если есть калькулятор, цену должен называть он. Если считает
модель — покажите ей ВСЕ правила, включая наценки.

**Условия оплаты разошлись между двумя сообщениями.** В сводке «предоплата
100%», а следующим сообщением «студия работает по предоплате 50%» — потому
что в финальном тексте стояла жёсткая константа. Правило: одно условие
считается один раз и используется везде.

**В заявке не было даты.** Владелец открыл письмо и не понял, свежая заявка
или недельной давности. Ставить дату и время первой строкой.

## 5.1. Грабли в коде бота, найденные 11.08.2026

Все три молча теряли заявки. Общее у них одно: **поломка выглядела
как нормальная работа**.

**Молчаливый выход неотличим от поломки.** Защита от повторных брифов
выходила `return` без единой строки в лог. Заявки нет, в журнале пусто —
час ушёл на поиск несуществующей ошибки в доставке почты, хотя отправка
даже не начиналась. Правило: **любое ветвление, которое отменяет
отправку, обязано писать в лог, что и почему пропущено.**

**Защита от спама, которая не забывает, — это потеря клиентов.**
`notified` был `Set` из ключей диалога без срока жизни. Человек оставил
телефон в понедельник, вернулся в пятницу с новым заказом — второй бриф
не приходил никогда. Теперь помним контакт и время: тот же контакт
в пределах шести часов — повтор, другой контакт или другой день — новая
заявка. Срок согласован с временем жизни разговора (`DIALOG_TTL_MS`).

Побочный эффект для проверок: **повторно проверить бриф с той же страницы
ВК нельзя** — придёт «Повтор». Либо назвать другой номер, либо перезапустить
приложение, либо подождать шесть часов.

**Примеры в промпте модель принимает за список для заполнения.**
Поле было написано так: `Каналы: <Telegram, ВКонтакте, WhatsApp, сайт —
что упоминалось>`. В брифе № 4 модель выписала все три, хотя клиент
не называл ни одного. Соседние поля написаны через «если называл» —
там честно стояло «не назван». Правило: **в шаблоне писать условие,
а не примеры**, и прямо указывать, что писать, когда данных нет.
Выдуманная подробность в заявке хуже её отсутствия: по такому брифу
звонят и говорят «вы писали, что вам нужен WhatsApp».

**Цену и реквизиты не отдавать модели.** Повтор правила из раздела 5,
но с новой стороны: когда дойдёт до предоплаты и QR, суммы и реквизиты
подставляет код по жёсткому шаблону. Модель ошибается в цифрах редко,
и обычно это неважно — здесь это деньги и доверие клиента.

## 6. Грабли выкатки на Amvera

**Приложения разные — код сам не переезжает.** В granat-kmv сайт и бот это
два РАЗНЫХ приложения Amvera, у каждого свой git и свой диск. Правка в
репозитории в бота не попадает, файл нужно загрузить в его «Репозиторий»
руками. На этом спотыкались трижды за один день.

Здесь проще: сайт и бот — одно приложение Node. Но если бот выделится в
отдельное — правило вступит в силу.

**Переменные окружения читаются только при старте.** Завёл переменную —
перезапусти приложение, иначе получишь `forbidden` на ровном месте.

**`git push -f amvera origin/<ветка>:master` берёт КОПИЮ ветки с компьютера,
а не с GitHub.** Без свежего `git fetch` уезжает старая версия, и push при
этом отрабатывает без единой ошибки. Проверять по хэшу в последней строке.
10.08.2026 так выкатили версию пятидневной давности.

**В PowerShell нельзя `git show ... > файл.py`.** Перенаправление `>` пишет
файл в UTF-16, Python такой файл не читает. Правильно —
`git checkout origin/<ветка> -- файл1.py файл2.py`: git пишет сам, без
участия оболочки, и берёт несколько файлов за раз.

### Добавлено 11.08.2026

**Amvera тянет код из СВОЕГО git, а не из GitHub.** В логе сборки это
видно строкой `Cloning into '/git'... HEAD is now at <хэш>`. Push в GitHub
на сайт не выкатывает ничего. Выкатка — только push в remote `amvera`.
Полдня ушло на ошибочный вывод «код загружают архивом»: строки
`Added /source/... to the archive` в логе — это внутренняя упаковка
Amvera ПОСЛЕ сборки, а не загрузка файлов человеком.

**Логов два, и они разные.** «Лог сборки» заканчивается на упаковке
архива и `Container builder has completed with exit code: 0`. Всё, что
пишет приложение, — в «логе приложения», это отдельное переключение
вверху страницы «Логи». Дважды присылали лог сборки вместо лога
приложения и искали в нём строки бота.

**Панель не обновляется сама.** Показывает срез на момент открытия
страницы, поэтому «висит» статус и «пропадают» свежие строки. Проверять
результат делом — открыть сайт, написать боту, — а не смотреть на панель.

**Статус «Выполняется сборка» дольше пары минут — это не сборка.**
Сборщик отрабатывает за 10–15 секунд (видно по времени в логе). Если
статус держится, значит новый контейнер не поднялся, и смотреть надо
лог приложения, а не ждать.

**Приложений в кабинете несколько.** У Гульнары рядом лежат `granat-site`
и `vibe-digital`. Открыли логи не того приложения и минут десять искали
в них бота ВК. Первым делом сверять имя в хлебных крошках вверху.

**Здесь сайт и бот — ОДНО приложение.** Переменные `VK_TOKEN`,
`VK_GROUP_ID`, `MAIL_TO` кладутся в приложение сайта. Соблазн положить
их в приложение `jarvis-bot` соседнего проекта велик, потому что там
живёт «бот», — но читать их будет некому.

**Выкатка чужой ветки без переключения локальной.** Если правки лежат
в ветке ассистента, а у Гульнары в папке другая — не надо ничего
переключать и сливать. Две команды, локальные файлы не трогаются:

    git fetch origin
    git push amvera origin/claude/<ветка>:master

Вторая команда берёт ветку из скачанной копии GitHub, а не из рабочей
папки. Проверять по последней строке: `старый..новый -> master`.

**Сброс тестовых заявок.** Журнал `/data/leads.jsonl` и счётчик
`/data/lead-counter.json` лежат на постоянном диске Amvera, куда нет
доступа ни из панели, ни из редактора. Поэтому сброс сделан переменной
`RESET_LEADS=любое-слово` — при следующем запуске журнал переименуется
в `leads-do-<дата>.jsonl`, счётчик обнулится. Повторно не срабатывает:
рядом кладётся файл-метка. Без метки одна забытая переменная стирала бы
журнал при каждом плановом перезапуске.

## 7. С чего начать

1. Завести бота у @BotFather, положить токен в переменную приложения.
2. В начало `server.js` добавить `dns.setDefaultResultOrder('ipv4first')`.
3. Написать транспорт Telegram по образцу `api/vk-bot.js`: приём сообщения,
   вызов того же ассистента из `api/brief.js`, ответ.
4. Обернуть запуск опроса в try/catch так, чтобы падение Telegram не
   останавливало сайт и ВК.
5. Проверить на живом клиенте весь путь: первое сообщение → согласие
   словом, а не только кнопкой → сбор брифа → заявка владельцу с датой.

Промпт, вопросы и формат брифа — общие. Правка в `api/brief.js` должна
менять все каналы сразу: чат на сайте, ВКонтакте и Telegram. Если появятся
три разных промпта, дальше они разъедутся и будут отвечать по-разному.
