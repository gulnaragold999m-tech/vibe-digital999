# 13 — Многостраничник: чек-лист и грабли

Этот файл — про то, **как добавлять страницы и не наступать второй раз**.
Механика сборки описана в `01-ARCHITECTURE.md`, здесь только порядок
действий, требования и ошибки, которые уже стоили времени.

Читать до первой новой страницы, а не после замечаний в Вебмастере.

---

## Что сборка проверяет сама — своих проверок не изобретать

`node build.js` при каждом запуске сверяет и печатает список замечаний:

- заголовок длиннее 65 символов — в выдаче обрежется;
- описание длиннее 160 или короче 110 символов;
- **два одинаковых заголовка или описания на разных страницах** — поиск
  выберет одну и посчитает вторую лишней;
- `parent` указывает на несуществующий адрес — крошки соберутся неверно;
- падеж в шаблоне: «в Краснодарский край» вместо «в Краснодарском крае».

Сборку это не роняет — файлы уже написаны, сайт работает. Но **список
замечаний означает, что страницу нельзя выкатывать**, пока он не пуст.
Последняя строка должна быть «Проверка мета-тегов: чисто».

Само собирается и вручную не пишется: меню, подвал, хлебные крошки
и `BreadcrumbList`, `canonical`, `sitemap.xml`, `llms.txt`, `FAQPage`
из блоков `<details class="faq-item">`, даты публикации и правки.

---

## Порядок добавления страницы

1. Запись в `src/pages.js`: `url`, `title`, `description`, `crumb`,
   `parent`, `file`, `lastmod`, при необходимости `offer` и `priority`.
2. Файл в `src/pages/`. Один `h1`, дальше `h2` по разделам.
3. `npm run build`. Дождаться «Проверка мета-тегов: чисто».
4. Поднять сайт локально и открыть страницу. Ссылки в меню, крошки,
   форма — глазами.
5. **Перелинковка.** Поставить ссылку на новую страницу минимум из двух
   мест: с родительской страницы и из смежной по смыслу. Без входящих
   ссылок поиск считает страницу второстепенной, даже если она в sitemap.
6. Выкатить (порядок — в `CLAUDE.md`).
7. Отправить адрес на переобход в Вебмастере.
8. Запись в `TASKS.md`.

## Требования к самой странице

- **Один `h1`.** Второй `h1` на странице — типовая ошибка вёрстки блоков.
- **Заголовок и описание уникальные.** Не «Услуги — Vibe Digital 999»
  на пяти страницах: сборка это ловит, но лучше писать сразу по-разному.
- **Коммерческий и информационный интент не смешивать.** «Заказать»,
  «цена», «под ключ» — страница услуги. «Как», «чем отличается»,
  «нужно ли» — блог со ссылкой на услугу.
- **Текст уникальный, а не переставленные абзацы соседней страницы.**
  Две почти одинаковые страницы конкурируют друг с другом, и поиск
  показывает не ту.
- Состав страницы услуги — в `01-ARCHITECTURE.md`, раздел «Что должно
  быть на каждой странице услуги».

## Филиалы и города внутри ОДНОГО клиента — не отдельные страницы

Самая дорогая ошибка в многостраничнике для клиента с несколькими точками.

Три филиала соблазняют сделать три копии всех страниц: три «о нас»,
три «цены», три «контакты». Так делают часто, и кончается это одинаково:

- поиск видит дублирующиеся страницы и выбирает из них одну, обычно не ту;
- человек попадает на страницу не своего филиала и уходит, не заметив
  переключателя.

**Правильно:** филиал — это выбор внутри страницы, а не отдельная ветка
сайта. Разделы не дублируются, расписание и контакты меняются по выбору.
Так сделано в кейсе автошколы «Старт» — `src/pages/case-avtoshkola.html`.

## Гео-страницы — наоборот, отдельные и постоянные

Разница с филиалами в том, что гео-страницы обслуживают **разные запросы
разных людей**, а не один бизнес в разных точках.

- Постоянный отдельный адрес: `/pyatigorsk/`, `/essentuki/`, `/kmv/`.
- `canonical` на себя, не на главную.
- Уникальный текст: не главная с заменённым названием города.
- В `sitemap.xml` попадают как обычные страницы.
- **Никаких редиректов по IP.** Определение региона — только мягкая
  подсказка в форме, которую человек может изменить. Робот, пришедший
  из другого региона, обязан увидеть то же, что видит человек.
  Подмена содержимого по IP — это клоакинг, за него понижают весь сайт.
- `hreflang` не нужен: язык один.

## Яндекс.Вебмастер

- **Адреса на переобход отправляются относительными:** `/pakety/`,
  а не `https://vibe-digital999.ru/pakety/`. Сайт зарегистрирован как
  `http://`, и абсолютный адрес с `https` Вебмастер отклоняет.
- После добавления пачки страниц — отправить `sitemap.xml` заново.
- Обход идёт днями, не часами. Проверять через неделю, а не назавтра.

## Яндекс.Метрика для многостраничника

Счётчик 110416869. Шесть целей уже созданы, зонтичная — `lead`.

- **Новые страницы наследуют цели автоматически:** счётчик и форма лежат
  в общих частях (`src/partials/`), а цели построены на JS-событиях,
  а не на адресах. Ничего дозаводить при добавлении страницы не нужно.
- **Дополнительные адреса счётчика должны быть разными.** Две одинаковые
  строки в настройках дают ошибку сохранения «Дополнительные адреса должны
  быть разными» — лишнюю строку удалить.

Что смотреть, когда страниц много:

| Отчёт | Зачем |
|---|---|
| Страницы входа | На какие страницы приходят из поиска и рекламы. Главная перестаёт быть единственной точкой входа — это и есть смысл многостраничника |
| Глубина просмотра | Ходят ли по внутренним ссылкам. 1,0–1,1 означает, что перелинковки нет или она не видна |
| Конверсии по страницам входа | Какая страница приносит заявки, а какая только трафик |
| Отказы по страницам | Страница с отказами сильно выше среднего отвечает не на тот запрос, по которому на неё приходят |

**База для сравнения, 6–9 августа 2026** (одностраничная версия):
441 посещение, 376 из них с карточки Яндекс Бизнеса, 37 секунд на сайте,
глубина 1,11, отказов 66%. С этими числами сравнивать результат
многостраничника, а не с «вроде стало лучше».

- **Реклама Яндекс Бизнеса метку ставит** — `utm_referer=geoadv_…`,
  не `utm_source`. Заявки её читают (`api/lead.js`, `utmFrom`).
  Региона в метке нет: карточка одна на все края.

## Чего на этом сайте сделать нельзя

- **Определить город посетителя по IP.** Прокси Amvera подставляет свой
  внутренний `10.x.x.x`, настоящий адрес до приложения не доходит.
  Код `/api/geo` оставлен и включится сам, если хостинг это починит.
  Подробности — `CLAUDE.md`, раздел про ловушки Amvera.
- **Считать что-либо по IP посетителя** — по той же причине. Ограничение
  частоты заявок считается по телефону, а не по адресу.
