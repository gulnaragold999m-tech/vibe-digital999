## Шаг 0. Диагностика — сначала посмотреть, потом править

Ничего не переписывать, пока не проверено:

1. **Счётчик на всех страницах?** Открыть исходный код каждой страницы (главная,
   печать/полиграфия, сайты и боты, портфолио, о нас, контакты, privacy) и найти
   `110961373`. Если счётчик вставлен в каждый шаблон копипастом — вынести в
   `templates/partials/metrika.html` (файл в комплекте) и подключить
   `{% include 'partials/metrika.html' %}` в общий `<head>`.
2. **Счётчик один?** Если где-то остался старый код Метрики с другим номером или
   дублем 110961373 — удалить лишнее.
3. **Счётчик не заблокирован согласием?** Ключевой пункт. Найти в коде баннера, что
   происходит при отказе/до нажатия «Принимаю». Если весь счётчик стартует только
   после согласия — **исправить**: обезличенный счёт должен идти всегда, под согласие
   ставится только `webvisor`. Иначе сайт невидим для Яндекс.Вебмастера и робота
   Яндекс.Бизнеса (на другом проекте студии это уже ловили).
4. **Имя ключа согласия.** В `partials/metrika.html` стоит `cookie_consent` как
   заглушка — заменить на то имя, которое реально использует баннер сайта. Новое не
   выдумывать.
5. Выписать, какие цели уже заведены в интерфейсе Метрики (Настройка → Цели), чтобы не
   плодить дубли.

## Шаг 1. Подключить скрипт целей

Файл `static/js/metrika-goals.js` из комплекта положить в `static/js/`.

Подключить перед `</body>` — в общем шаблоне, а не в каждой странице:

```html
<script src="{{ url_for('static', filename='js/metrika-goals.js') }}" defer></script>
```

Скрипт счётчик не инициализирует, только шлёт цели. Если `ym` не найден (блокировщик) —
молча ничего не делает, ошибок в консоли не даёт.

## Шаг 2. Разметить кнопки

Телефон, WhatsApp, Telegram и почта ловятся автоматически по `href` — там ничего делать
не надо. Остальное размечается атрибутом прямо в HTML:

```html
<a href="#zakaz" data-goal="price_click">Смотреть цены</a>
<button data-goal="bot_demo_start">Запустить демо бота</button>
<a href="/portfolio" data-goal="portfolio_view">Портфолио</a>
```

Кнопке «Принимаю» в cookie-баннере добавить `data-goal="cookie_accept"` — отдельный код
не нужен.

## Шаг 3. Форма заявки

Цель ставится **после успешной отправки**, не по клику по кнопке. Иначе в отчёте будет
40 заявок при 12 реальных.

- Форма с обычным POST и редиректом → надёжнее всего **цель «Посещение страниц»** на
  страницу «Спасибо», без кода вообще (см. шаг 4). Дополнительно можно разметить форму:
  `<form method="post" data-goal-form="lead_form">`.
- Форма на fetch/AJAX → вызвать вручную в ветке успеха:

```js
if (res.ok) {
  window.granatGoal('lead_form', { form: 'kontakty' });
  // дальше показ «спасибо»
}
```

## Шаг 4. Завести цели в интерфейсе Метрики

Метрика → Настройка → Цели → Добавить цель → тип **JavaScript-событие**, в поле
«Идентификатор цели» — имя из таблицы. Без этого шага цель не появится в отчётах, даже
если код её отправляет.

| Цель | Что считает | Как срабатывает |
|---|---|---|
| `lead_form` | заявка отправлена | вручную после успеха / `data-goal-form` |
| `call_click` | клик по телефону | автоматически |
| `whatsapp_click` | переход в WhatsApp | автоматически |
| `telegram_click` | переход в Telegram | автоматически |
| `email_click` | клик по почте | автоматически |
| `price_click` | дошёл до цен | `data-goal="price_click"` |
| `bot_demo_start` | запустил демо бота | `data-goal="bot_demo_start"` |
| `portfolio_view` | открыл портфолио | `data-goal="portfolio_view"` |
| `scroll_75` | дочитал страницу | автоматически |
| `cookie_accept` | принял куки | `data-goal="cookie_accept"` |

Отдельно — цель без кода: тип **Посещение страниц**, условие «url содержит `/spasibo`»
(или тот адрес, куда уходит форма после отправки).

**Ключевые цели:** пометить `lead_form` и `call_click` как ключевые. Если потом
запускать Директ, автостратегии будут учиться на заявках, а не на просмотрах — без этой
галки реклама оптимизируется на трафик.

## Шаг 5. Маскировка полей в Вебвизоре (152-ФЗ)

Вебвизор пишет видео действий посетителя. Без маскировки в запись попадает телефон и
имя из формы. На каждое поле с персональными данными:

```html
<input type="tel"   name="phone" class="ym-disable-keys">
<input type="text"  name="name"  class="ym-disable-keys">
<input type="email" name="mail"  class="ym-disable-keys">
```

Скрыть в записи блок целиком: `class="ym-hide-content"`.
Записывать поле явно (поиск, выбор тиража): `class="ym-record-keys"`.

## Шаг 6. Разбивка по направлениям

Скрипт при каждой загрузке шлёт параметр `section`, взятый из адреса страницы
(`/pechat/...` → `pechat`). Если структура адресов не совпадает с направлениями
(полиграфия / сайты и боты) — задать вручную в шаблоне: `<body data-section="pechat">`.

Смотреть потом: **Отчёты → Содержание → По параметрам визитов → section**.

## Настройки самого счётчика (делается в интерфейсе, не кодом)

1. **«Привязать к Вебмастеру»** — сейчас не нажато. Нажать: в Метрике появятся
   поисковые запросы и страницы входа. Для SEO это половина работы.
2. **«Принимать данные только с указанных адресов»** — галка стоит, это правильно. Но
   проверить: если сайт открывается и на `www.granat-kmv.ru`, и без `www`, оба адреса
   должны быть в списке, иначе часть визитов молча потеряется.
3. **Вебвизор** — включить запись и поставить «Не записывать содержимое полей»
   (вместе с классами из шага 5).
4. **Фильтры** — добавить фильтр своих визитов, чтобы собственные заходы не портили
   конверсию.
5. Часовой пояс МСК, «Включая поддомены» выключено — оставить как есть.

## Приёмка

1. `granat-kmv.ru/?_ym_debug=1` → F12 → Console: строки Метрики с номером **110961373**,
   ровно один счётчик.
2. Пройти по всем разделам — счётчик грузится на каждой странице.
3. Клик по телефону и по кнопке с `data-goal` → в консоли `reachGoal`.
4. Тестовая заявка → Метрика → **Отчёты → В реальном времени**: визит и цель в течение
   минуты.
5. Открыть сайт в режиме инкогнито до нажатия «Принимаю» — визит всё равно должен
   считаться (проверка пункта 3 из шага 0).
6. Через сутки открыть Вебвизор: вместо телефона в записи звёздочки.

## Чего не делать

- Не трогать репозиторий `C:\granat-kmv` (Next.js) — это не тот сайт.
- Не ставить второй счётчик «для рекламы»: один счётчик, разные цели.
- Не включать `trackHash` — якоря начнут считаться визитами и испортят показатель
  отказов.
- Не вешать Google Analytics: для рунета Метрика даёт больше (Вебвизор, связка с
  Вебмастером и Директом), а второй счётчик — лишний скрипт в загрузке.
