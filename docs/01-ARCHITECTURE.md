# 01 — Архитектура сайта

Многостраничный сайт. До 9 августа 2026 был одностраничником — почему
переехали и как теперь устроено, ниже.

## Почему не одна страница

Одностраничник упёрся в потолок, который не снимается ни текстами, ни
разметкой, ни ссылками. Поиск на один запрос выбирает **один** документ
с сайта. Когда услуг семь, а документ один, он релевантен каждому запросу
на седьмую часть — и проигрывает конкуренту, у которого под «разработка
телеграм бота» есть страница ровно про это.

Второй эффект: чем больше страниц, тем быстрее набираются низкочастотные
запросы, а через них — поведенческие факторы, на которых потом растёт всё
остальное. Одностраничнику расти нечем.

Главная при этом осталась длинной и живой: она хаб и витрина, с неё ведут
ссылки вниз, в разделы.

## Правило распределения запросов

Коммерческий интент («заказать», «цена», «под ключ») — на страницу услуги.
Информационный («как», «чем отличается», «нужно ли») — в блог, со ссылкой
на услугу. **Смешивать на одной странице нельзя:** это два разных человека,
и страница может ответить хорошо только одному из них.

## Как страницы собираются

Общие куски лежат по одному разу, страницы собираются из них скриптом.

```
src/pages.js          карта сайта: адреса, заголовки, описания, даты, цены
src/partials/         шапка, подвал, <head>, форма заявки
src/pages/*.html      тексты страниц
build.js              склеивает всё в public/ + sitemap.xml + llms.txt
```

```bash
npm run build     # собрать вручную
npm start         # соберёт сам, перед запуском сервера
```

Собранные файлы лежат в репозитории вместе с исходниками: если сборка
когда-нибудь упадёт, на сервере останется рабочая прошлая версия, а не
пустой сайт.

**Файлы в `public/uslugi/`, `public/blog/`, `public/portfolio/` и рядом
править бессмысленно** — следующая сборка их перезапишет. Исходники в `src/`.

Главная (`public/index.html`) и политика (`public/privacy.html`) собраны
вручную и в сборку не входят: на главной живут квиз, чат, калькуляторы
и фон на Canvas — под шаблон это не ложится и не должно.

## Что собирается само

Из `src/pages.js` берутся не только адреса:

- **меню и подвал** — новая страница появляется в них сразу;
- **хлебные крошки** и разметка `BreadcrumbList` — из поля `parent`;
- **sitemap.xml** — только страницы без `noindex`;
- **llms.txt** — карта сайта для ИИ-поиска;
- **`datePublished` / `dateModified`** — из полей `published` и `lastmod`.

Разметка `FAQPage` собирается **из текста страницы**, а не пишется отдельно:
скрипт читает блоки `<details class="faq-item">`. Иначе ответ на странице
рано или поздно поправят, а в разметке забудут, и поиск покажет в выдаче
то, чего на странице уже нет.

## Первый экран главной

Экран обязан за три секунды ответить на четыре вопроса: что мы делаем,
для кого, какой результат, что нажать. Порядок блоков и есть ответ,
менять его нельзя.

| Что | Зачем |
|-----|-------|
| Маркер специализации со значком логотипа | что мы делаем и для кого |
| H1 «Сайты и Telegram-боты, которые приводят заявки» | какой результат |
| Строка боли: «Сайт есть, а заявок нет» | почему это про читателя |
| Подзаголовок с ценой и сроком | как и за сколько |
| Одна главная кнопка «Получить расчёт проекта» | что нажать |
| Вторая ссылка «Посмотреть кейсы» | для тех, кому рано нажимать |
| Три строки доверия: ИП и договор, исходники, срок ответа | почему не страшно нажать |
| Демо «заявка в Telegram» справа | как выглядит результат |
| Строка географии | закрывает вопрос «а вы только по КМВ?» |

**Чего на первом экране быть не должно.** Декоративных счётчиков без пользы
для клиента: до 11.08.2026 здесь стояли «24/7», «4 ниши в работе» и
«0 конструкторов», их заменили строки доверия. Каждая строка доверия обязана
быть проверяемой — не можете подтвердить делом, не ставьте. Второй
равнозначной кнопки рядом с главной. Спорных абсолютов вроде «ничего
не ломается».

**Крючки геоподмены трогать нельзя.** `data-geo-tagline` стоит на строке боли,
`data-geo-sub` на подзаголовке, `data-geo-proof` на пустом абзаце над кнопками.
Главная кнопка обязана оставаться ПЕРВОЙ в `.hero-actions`: скрипт региональной
подмены находит её селектором `.hero-actions .btn-action` и меняет ей текст
и адрес.

**Раскладка.** От 1000px — две колонки: текст слева, демо справа. Уже — одна
колонка, демо уходит под кнопки. На низких экранах (до 700px по высоте) демо
скрывается, строки доверия остаются.

**Правый край на телефоне.** Панель связи закреплена справа и занимает нижнюю
половину экрана. Всё, что ниже подзаголовка, отступает от правого края
на 2.7rem, иначе иконки ложатся на главную кнопку и палец попадает в WhatsApp.
Контейнер `#chat-widget` шире своих кнопок, поэтому на нём стоит
`pointer-events: none`, а клики принимают только прямые потомки — без этого
его пустая часть съедала нажатия по тому, что лежит под ней.

## Что должно быть на каждой странице услуги

1. `h1` с ключевым запросом, один на странице.
2. Цена и срок в первом экране — два вопроса, ради которых страницу открыли.
3. «Что входит» — список без воды.
4. 6–10 вопросов, сформулированных так, как их задают вслух.
5. Форма заявки с заранее подставленной услугой.
6. Ссылки на смежные услуги, кейс и статью блога.

## Общие стили и скрипты

`public/assets/css/site.css` и `public/assets/js/site.js` — общие для всех
внутренних страниц. Браузер скачивает их один раз и дальше берёт из кэша.

Главная свои стили держит внутри себя: у неё их 2200 строк, и половина
нужна только ей — фон на Canvas, квиз, чат, тест скорости.

## Технические требования

- Вес внутренней страницы без картинок — до 60 КБ в сжатом виде.
- Шрифты свои, в `/assets/fonts`, наружу не уходит ни один запрос.
- Картинки: `alt`, `loading="lazy"` для всего ниже первого экрана.
- Первая картинка экрана — **без** `lazy`: она и есть то, чего ждут.
- Анимации отключаются при `prefers-reduced-motion: reduce`.
- Горизонтальной прокрутки нет ни на одной странице ни при какой ширине.
- Плашка о куках стоит под шапкой, а не поверх: поверх она перехватывала
  нажатия по кнопке меню — единственному входу в разделы с телефона.
