# Объёмная карточка товара или услуги

Два сценария. Выбор — по одному признаку: **видна ли верхняя грань.**

| Видно | Сценарий | Метод | Пример |
|---|---|---|---|
| Лицо + бок + КРЫШКА | 1. Коробка | честное 3D | `references/korobka.html` |
| Лицо + корешок, низ ровный | 2. Книга | плоский скос | `references/primer.html` |

Оба примера самодостаточные: открываются в браузере, копируются
в проект, ничего не требуют. **Начинать с них, а не писать заново.**

## Сценарий 1. Коробка на неоновой плате

Когда объект должен выглядеть монолитной пачкой с откидным колпаком,
стоящей на светящейся плате.

### Каркас

```css
.box-scene { perspective:2000px; perspective-origin:50% 8%; }
.main-box  { transform-style:preserve-3d;
             transform:rotateX(12deg) rotateY(-28deg); }

.face-front  { transform:translate3d(0,0,var(--pol)); }
.face-left   { left:0; width:var(--glub); transform-origin:left center;
               transform:translateZ(var(--pol)) rotateY(-90deg); }
.face-top    { top:0;  height:var(--glub); transform-origin:center top;
               transform:translateZ(var(--pol)) rotateX(90deg); }
```

`--pol` — ПОЛОВИНА глубины. Три вещи, на которых спотыкаются:

1. **Порядок в `transform` решает всё.** Сначала выдвинуть грань вперёд,
   потом повернуть вокруг ребра. Наоборот (`rotateY(-90deg) translateZ()`)
   сдвиг пойдёт по УЖЕ ПОВЁРНУТОЙ оси: боковина отлетает от коробки,
   крышка улетает вверх. Проверено — выглядит именно как поломка.
2. **`translateZ` у боковой и верхней граней обязателен.** Лицо стоит
   на `+половина`, а грань без сдвига — от нуля, и разница в полглубины
   вылезает козырьком: КРЫШКА ВЫСТУПАЕТ за край коробки отогнутой
   пластиной. Коварство в том, что силуэт при этом закрывается
   и на общем плане версия выглядит правдоподобно — козырёк виден
   только на увеличенном вырезе угла.
3. **Знак `rotateX` подбирается глазами.** Отрицательный прячет крышку,
   положительный показывает. Значение зависит от `perspective-origin`,
   вычислять бесполезно — быстрее отрисовать и посмотреть.

### Шов откидного колпака

Тёмная прорезь и светлый блик под ней, на лице и на боку **на одной
высоте от верхнего ребра**:

```css
:root{ --shov:46px; }        /* одна переменная на обе грани */
.shov{ background-image:linear-gradient(180deg,
    transparent 0 calc(var(--shov) - 2px),
    rgba(0,0,0,.7)        calc(var(--shov) - 2px) var(--shov),
    rgba(255,255,255,.12) var(--shov) calc(var(--shov) + 2px),
    transparent calc(var(--shov) + 2px)); }
```

Двумя отдельными числами линии разъедутся на ступеньку. Рисовать фоновым
слоем, а не элементом: псевдоэлементы граней заняты бликами на рёбрах.
Весь текст — строго ниже шва.

### Подиум под коробкой

Это **нижняя грань коробки**, а не отдельный прямоугольник на полу:
гранью он лежит ровно под дном при любом развороте, отдельный элемент
пришлось бы совмещать вручную и он ехал бы при каждой правке угла.

```css
.face-bottom{ top:100%; transform-origin:top center;
  transform:translateZ(var(--pol)) rotateX(-90deg) translateY(-45px);
  border:2px solid var(--acc); border-radius:16px;
  box-shadow:0 0 20px var(--acc), 0 0 60px var(--acc2); }
```

Рамку делать ШИРЕ дна: ровно по дну её не видно, коробка закрывает.

### Плата

Горизонтальная плоскость через `rotateX(75deg)`, края растворяются
маской, иначе прямоугольник обрубается по границе кадра:

```css
mask-image:radial-gradient(circle at 50% 50%, #000 38%, transparent 78%);
```

Дорожки — прямые с прямыми углами и площадками на концах, линиями в SVG.
Так рисуют разводку, и так она узнаётся. Картинкой не делать: линии
остаются резкими на любом размере и красятся цветом карточки.

### Текст на боковине

```css
.face-left span{ writing-mode:vertical-lr; transform:rotateY(180deg); }
```

Бок обращён к зрителю изнанкой, поэтому буквы зеркалятся.
**`rotate(180deg)` эту задачу НЕ решает** — он переворачивает строку
снизу вверх, а зеркало оставляет. Нужен разворот вокруг вертикальной
оси. У крышки та же беда по другой оси: без `rotateX(180deg)`
на содержимом «V» читается как «Λ».

## Сценарий 2. Книга

Когда объект стоит вертикально и его нижний край должен быть строго
параллелен полу.

**Честное 3D здесь разваливается.** Развёрнутая грань живёт в своей
плоскости, перспектива искажает её отдельно от обложки, и нижние рёбра
идут под разными углами — в левом нижнем углу вылезает серый клин.
Это не ошибка кода, а следствие честной перспективы: пять правок подряд
его не закрыли.

```css
.book        { transform:skewY(-6deg); border-radius:0 12px 12px 0; }
.book::before{ content:"Название · от 35 000 ₽";
  position:absolute; right:100%; top:0; height:100%; width:45px;
  margin-right:-1px;                    /* закрывает субпиксельный просвет */
  transform-origin:right center;
  transform:skewY(-12deg);              /* ТОТ ЖЕ знак, что у обложки */
  writing-mode:vertical-lr;
  display:flex; align-items:center; justify-content:center; }
```

**Знаки одинаковые, углы складываются.** Встречные (`-6` и `+6`) —
правдоподобная и частая ошибка: корешок наследует наклон обложки,
собственный `+6` его обнуляет, грань встаёт вертикально рядом
с наклонной обложкой, стык расходится.

**Текст на корешке — только `writing-mode: vertical-lr`.** Никакого
`rotate(180deg)`: у плоской грани нет изнанки, зеркалиться нечему,
а поворот перевернёт строку снизу вверх. И никаких `rotateZ`
со сдвигом `translateZ` — такие комбинации подбираются под конкретную
толщину и промахиваются мимо торца, стоит её поменять.

**Толщина — от ширины, а не числом из головы.** Около 14%: книга 320px →
корешок 45px, книга 600px → 84px. Перенести 45px на широкую книгу —
получить 7% и плоскую панель.

## Общее для обоих сценариев

**Свет.** Обложка — не заливка, а радиальный градиент из центра к краям.
Боковые и верхние грани темнее лица. Корешок светлее у сгиба и темнее
на дальнем ребре: наоборот быть не может, грань уходит от света —
ошибка в направлении читается торчащим светлым клином.

**Блик на сгибе** — 1–2px, `inset 1px 1px 0 rgba(255,255,255,.2)` или
тонкая полоса. **Без цветного ореола:** со свечением он читается
не ребром, а светящейся щелью, и тем сильнее, чем ярче акцент.

**Тень.** Двумя слоями: `box-shadow` на теле плюс отдельное размытое
пятно на полу. Одного `box-shadow` мало — он наклоняется вместе с телом,
а лежать должен на плоскости.

**Значения в таблице на обложке** — акцентным неоном со свечением,
не белым и не бледным оттенком акцента. Бледный рядом с ярким
на соседней карточке читается белёсым, и серия выглядит собранной
по-разному.

### Анимация не переживает скриншот

Если карточка отдаётся картинкой, `@keyframes` в ней не будет: скриншот
берёт один кадр, и анимированный градиент на нём выглядит обычной
полосой. Импульсы на дорожках расставлять как остановленный кадр —
несколько ярких точек в разных местах разводки. Нужна настоящая
беготня — это другой формат вывода, видео или GIF, и другая задача.
Для сторис окупается, для карточки товара в Яндекс Бизнесе не нужна:
там принимается статичная картинка.

### Цена и срок — из одного места

Не вписывать в разметку. Брать из единого прайса проекта и подставлять
при сборке. Цена, записанная руками в макет, устаревает за сутки: так
на первом же макете остались старые штрафы и срок «3–5 дней» вместо
«3 дня» из прайса. Клиент читает расхождение как обман, а не опечатку.

### Чего на карточке быть не должно

- **Выдуманных замеров.** «Загрузка 1,1 с», «PageSpeed 92» — если замера
  не было, это то же самое, что выдуманная цена.
- **Чужих шаблонных пунктов.** «Подходит для изучения», «понятная подача
  материала», «Архитектура / Безопасность / Масштаб» — следы заготовок,
  которые ничего не обещают и ни к чему не привязаны.
- **Обещаний, которых нет в договоре.**

## Проверка. Без неё ни одна версия не годится

**Нарисовал — открой и посмотри.** Пять переделок коробки подряд
случились именно потому, что код выглядел правильным.

**Смотреть на увеличенных вырезах.** Зеркальный текст, щель в сгибе
и косой угол на общем плане выглядят правдоподобно. Вырезать кусок
и увеличить втрое-вчетверо.

**Спорные места решать числами.** Печатать при сборке геометрию:

```
книга: слева 136, справа 724, ширина 588, верх 354, низ 1363
корешок: 84px / matrix(1, -0.212557, 0, 1, 0, 0) / 26px
```

Вопрос «одинаковые карточки или мне кажется» закрывается за полминуты.

**Не понимаешь, куда смотрит ось, — раскрась.** Временно залить грань
`linear-gradient(90deg,#FF0000,#00FF00)` и посмотреть, где какой конец.
Полминуты вместо трёх перекладываний вслепую.

**Проверка переполнения в сборщике.** Текст берётся из прайса, прайс
меняется: длинное название молча уедет за край, и увидят это уже
у клиента.

## Для Яндекс Бизнеса

- Формат: 3:4 (1080×1440) или квадрат — показывается целиком
  и в карточке, и в ленте ВК.
- **Цена на картинке не обязательна и рискованна.** У Яндекса цена —
  отдельное поле рядом с изображением; цифра на картинке её дублирует,
  а дубль разъезжается. Плюс модерация снимает изображения
  с рекламными наложениями.
- Логотип на изображении — не больше пятой части кадра.
- Не дублировать названия позиций: две с одинаковым названием склеятся.
- Отклонили — держать рядом сдержанный вариант: состав, кому подходит,
  срок; без цены и без призыва.
