# Бот в сообществе ВКонтакте — чек-лист для любого проекта

Переносится в любой проект, где делают бота ВК: автошкола, типография,
студия. Ничего специфичного для одного сайта здесь нет — только то, что
повторится в каждом боте.

Собрано на живых запусках: granat-kmv (09–10.08.2026, Python) и
vibe-digital999 (11.08.2026, Node.js). Каждая ловушка ниже стоила часов,
а не выдумана из документации ВК.

**Раньше это лежало как `docs/VK-BOT-CHEKLIST.md` в ветке
`claude/vk-bot-setup-vuryya`** и в самом файле стояла оговорка: номер
не поставлен, потому что нумерованные `docs/NN-…` разъехались по веткам
и файлов с номером 12 стало три. Оговорка была верной, а лечение неполным:
файл всё равно жил в одной ветке и в другие проекты не попадал.
13.08.2026 при сведении веток он стал навыком — навык копируется папкой
и подхватывается сам.

## 1. Настройки в самом ВК — порядок жёсткий

Следующий пункт не появляется в интерфейсе, пока не сделан предыдущий.
Проверено 11.08.2026.

1. **Управление → Сообщения → включить «Сообщения сообщества».**
   Без этого бот не получит ни одного сообщения.

2. **Управление → Сообщения → «Настройки для бота» → «Возможности ботов»
   в положение «Включены» → нажать «Сохранить».**
   Без «Сохранить» ВК отвечает ошибкой **912**, причём сообщения приходят,
   а ответить бот не может — по логу непонятно почему.

3. **Там же галочка «Добавить кнопку „Начать“» → снова «Сохранить».**
   Переключатель и галочка сохраняются **отдельно**, одного нажатия мало.
   Кнопка заменяет человеку пустое поле ввода: нажал — разговор начался,
   не надо придумывать первую фразу.
   Галочку «Разрешать добавлять сообщество в чаты» не ставить, если бот
   рассчитан на личную переписку: в групповом чате он будет мешать.

4. **Ключ доступа: Управление → Работа с API → Ключи доступа → Создать ключ.**
   Отметить **две** галочки:
   - «Сообщения сообщества» — читать и писать;
   - «Управление сообществом» — чтобы бот сам включал Long Poll.

   **Ключ показывается один раз.** Не скопировали — создавайте новый.
   Лишние права не отмечать: ключ виден серверу и живёт в переменных,
   и чем меньше он умеет, тем дешевле его утечка.

5. **Long Poll руками не включать** — это делает код при запуске. Почему,
   в следующем разделе.

6. **Написать сообществу любое сообщение со своей личной страницы.**
   Пока человек не написал первым, ВК запрещает сообществу писать ему —
   ошибка **901**. Логика ровно как с кнопкой «Старт» в Telegram.
   Нужно, чтобы заявки приходили владельцу в ВК.

## 2. Long Poll включает код, а не человек

11.08.2026 раздел «Работа с API → Long Poll API» **не нашёлся в интерфейсе
ВК** ни по одному пути: правое меню Управления заканчивается на «Журнал
действий», прямой адрес `vk.ru/club<ID>/settings?act=api` перебрасывает
на «Основную информацию». Полдня ушло на поиски раздела, которого там,
похоже, больше нет.

Метод `groups.setLongPollSettings` делает то же самое одним запросом.
Разовое включение из адресной строки браузера:

    https://api.vk.com/method/groups.setLongPollSettings?v=5.199&group_id=НОМЕР&enabled=1&api_version=5.199&message_new=1&access_token=КЛЮЧ

Ответ `{"response":1}` — включено, настройка остаётся в ВК навсегда.

**Порядок параметров не случайный: `v` первым, `access_token` последним.**
Токен длинный, при копировании обрывается именно хвост. Если `v` стоит
в конце — он теряется, и ВК отвечает ошибкой 8 «v is required». С токеном
в конце обрыв даёт понятную ошибку 5 про токен.

Лучше сразу заложить в код автовключение при старте — тогда при переезде
на другое сообщество достаточно поменять токен и номер группы:

```js
async function ensureLongPollSettings(groupId) {
  const res = await vkApi('groups.setLongPollSettings', {
    group_id: String(groupId),
    enabled: '1',
    api_version: API_VERSION,
    message_new: '1',
  });
  // Отказ не смертелен: настройки могли выставить руками раньше.
  // Пишем понятное предупреждение и всё равно пробуем подключиться.
}
```

Признак успеха в логе: `Long Poll включён, подписка на входящие есть`.

## 3. Коды ошибок ВК

| Код | Что значит | Что делать |
|---|---|---|
| **5** | `User authorization failed` | Ключ отозван — выпустить новый. Но если тот же токен работает в приложении, значит он **обрезался при копировании**: брать значение из переменных окружения, а не из окна ВК |
| **8** | `v is required` | Из адреса потерялся хвост `&v=5.199`. Ставить `v` первым параметром |
| **15** | `Access denied` | У ключа нет нужного права — пересоздать с обеими галочками |
| **27** | Ключ выдан не тому сообществу | Проверить номер группы |
| **100** + текст про `longpoll ... not enabled` | Long Poll выключен | **Не про параметры запроса**, хотя код 100 обычно означает именно их. Один код у ВК значит разное — читать текст, а не только номер |
| **901** | Сообществу нельзя писать человеку первым | Человек должен написать сообществу хотя бы раз |
| **902** | Приватность получателя запрещает | Ничего не сделать со стороны бота |
| **911** | Слишком много рядов в клавиатуре | Максимум 10 рядов и 5 кнопок в ряду. 12 категорий раскладывать по две в ряд, а не резать список |
| **912** | Возможности ботов не включены | См. пункт 2 первого раздела |
| **914** | Сообщение длиннее допустимого | Предел 4096, резать самим на 4000 |

**Расшифровывать коды прямо в логе.** Через месяц «ошибка 901» в логах
не скажет ничего тому, кто будет разбираться. Подсказку для кода 100
делать зависимой от текста ошибки: неверная подсказка хуже, чем никакой —
по ней чинят не то место.

**ВК отвечает `200 OK` даже на ошибку.** Причина лежит внутри тела
в поле `error`. Проверять HTTP-код бесполезно, разбирать надо тело.

## 4. Что должно быть в коде бота

**Long Poll, а не вебхук.** Вебхук требует, чтобы ВК стучался снаружи:
лишний открытый адрес и перенастройка при каждом переезде.

**Бесконечный цикл с переподключением.** Коды `failed` от ВК:
`failed:1` — устарел `ts`, ВК прислал новый, просто подставить;
`failed:2` и `3` — протух ключ или пропала история, брать новый сервер.
Пауза между попытками растёт, но не больше минуты: если ВК лежит, долбить
его каждую секунду бессмысленно, а сдаваться нельзя — он вернётся.

**Ошибка бота не должна ронять процесс.** В granat-kmv 10.08.2026 Telegram
не ответил при старте, ошибка дошла до верха и остановила программу —
вместе с ней умер бот ВК, то есть ровно тот канал, который заведён на
случай смерти Telegram. Запуск каждого бота оборачивать так, чтобы падение
не уносило остальное.

**Сообщения от самого сообщества игнорировать.** У них `from_id < 0` —
это ответ администратора из чата ВК. Отвечать на них значит разговаривать
с самим собой.

**Структура ответа зависит от версии API.** В 5.103+ сообщение лежит
в `object.message`, в старых — прямо в `object`. Поддерживать обе:
`update.object?.message || update.object`.

**Лимит на человека.** 30 сообщений в час защищают счёт за модель от
шутника, который решит поговорить с ботом до утра.

**Контакт отправлять владельцу СРАЗУ**, не дожидаясь ответа модели. Если
модель откажет, заявка всё равно будет у вас.

**`random_id` обязателен** в `messages.send`: по нему ВК отбрасывает дубли,
если сеть моргнула и запрос ушёл дважды. Должен помещаться в int32.

**Разметки в ВК нет** — ни жирного, ни курсива. HTML-теги отобразятся
буквально. Структуру держать переносами строк и эмодзи.

**Голосовые ВК часто расшифровывает сам** и кладёт текст в `transcript`
объекта `audio_message` при `transcript_state: "done"`. Бесплатно и уже
готово — брать оттуда. Если читать только `message.text`, бот на голосовое
не ответит вообще, и человек решит, что бот сломан.

## 5. Три ошибки, которые молча теряют заявки

Общее у них одно: **поломка выглядит как нормальная работа.**

**Молчаливый выход неотличим от поломки.** Защита от повторов выходила
`return` без единой строки в лог. Заявки нет, в журнале пусто — час ушёл
на поиск несуществующей ошибки в доставке. Правило: **любое ветвление,
которое отменяет отправку, обязано писать в лог, что и почему пропущено.**

**Защита от спама, которая не забывает, — это потеря клиентов.** Память
«кому уже отправляли» была множеством без срока жизни. Человек оставил
телефон в понедельник, вернулся в пятницу с новым заказом — второй бриф
не пришёл никогда. Помнить надо контакт **и время**: тот же контакт
в пределах нескольких часов — повтор, другой контакт или другой день —
новая заявка.

Побочный эффект для проверок: **повторно проверить бриф с той же страницы
нельзя** — придёт «Повтор». Либо другой номер, либо перезапуск, либо ждать.

**Примеры в промпте модель принимает за список для заполнения.** Поле было
написано как `Каналы: <Telegram, ВКонтакте, WhatsApp — что упоминалось>`,
и модель выписала все три, хотя клиент не называл ни одного. Соседние поля
написаны через «если называл» — там честно стояло «не назван». Правило:
**в шаблоне писать условие, а не примеры**, и прямо указывать, что писать,
когда данных нет. Выдуманная подробность в заявке хуже её отсутствия:
по такому брифу звонят и говорят «вы писали, что вам нужен WhatsApp».

## 6. Разговорные грабли — не про код

Собраны на живых клиентах granat-kmv 10.08.2026.

**Согласие только кнопкой — петля без выхода.** Человек написал «нужно
100 визиток срочно», получил приветствие. Написал имя — приветствие снова.
Считать согласием и короткие слова: «да», «хорошо», «согласна». На второй
раз слать не то же приветствие, а короткую подсказку.

**Приветствие обещало то, чего бот не делает.** В тексте было «понадобится
ваше имя», хотя во ВК бот имя берёт из профиля. В приветствии описывать
ровно то, что бот сделает следующим шагом.

**Первая фраза клиента терялась.** Человек приходит не с пустыми руками.
Эту фразу запомнить и после согласия проиграть заново, а не заставлять
повторяться.

**Цену считает код, а не модель.** В прайсе, который видит модель, забыли
показать множители — срочный заказ оценён в 450 ₽ вместо 585 ₽. Если есть
калькулятор, цену называет он. Если считает модель — показать ей ВСЕ
правила, включая наценки. Суммы, реквизиты и QR для оплаты подставляет
код по жёсткому шаблону: модель ошибается в цифрах редко, и обычно это
неважно — здесь это деньги и доверие клиента.

**Условия оплаты разошлись между двумя сообщениями.** В сводке «предоплата
100%», следующим сообщением «студия работает по предоплате 50%» — в финальном
тексте стояла жёсткая константа. Одно условие считается один раз
и используется везде.

**В заявке не было даты.** Владелец открыл письмо и не понял, свежая заявка
или недельной давности. Ставить дату и время первой строкой.

## 7. Ловушки хостинга Amvera

**Переменные окружения читаются только при старте.** Завели переменную —
перезапустите приложение, иначе получите отказ на ровном месте.

**IPv6 не работает.** Всё, что ходит наружу, обязано идти по IPv4, иначе
соединение висит до таймаута и выглядит как «сервис не отвечает».
В Node первой строкой: `require('node:dns').setDefaultResultOrder('ipv4first')`.
Это ставит IPv4 первым, а не выкидывает IPv6 — обычному клиенту хватает.

**Настоящий IP посетителя не доходит.** Прокси подставляет свой внутренний
`10.x.x.x`. Город по IP не определить, ограничение частоты считать
по телефону или нику, а не по адресу.

**Amvera тянет код из СВОЕГО git, не из GitHub.** В логе сборки это видно
строкой `Cloning into '/git'... HEAD is now at <хэш>`. Push в GitHub не
выкатывает ничего. Строки `Added /source/... to the archive` — внутренняя
упаковка Amvera ПОСЛЕ сборки, а не загрузка файлов человеком; на этом
можно надолго уйти в неверную сторону.

**Логов два, и они разные.** «Лог сборки» заканчивается на упаковке архива
и `exit code: 0`. Всё, что пишет приложение, — в «логе приложения», это
отдельное переключение вверху страницы.

**Панель не обновляется сама** — показывает срез на момент открытия.
Проверять результат делом: открыть сайт, написать боту.

**Статус «Выполняется сборка» дольше пары минут — это не сборка.**
Сборщик отрабатывает за 10–15 секунд. Если статус висит, значит новый
контейнер не поднялся: смотреть лог приложения, а не ждать.

**Приложений в кабинете несколько.** Легко открыть логи чужого проекта
и искать в них своего бота. Сверять имя вверху страницы.

**Где живёт бот — важно.** Если сайт и бот в одном приложении, переменные
кладутся в приложение сайта. Если бот отдельным приложением (как
`jarvis-bot` в granat-kmv) — у него свой git, свой диск и свои переменные,
и правка в репозитории сайта до него не доедет.

**Постоянный диск `/data` недоступен из панели.** Ни редактора, ни
файлового менеджера. Всё, что нужно там почистить или сбросить, делается
кодом — например, разовой переменной окружения, которая срабатывает один
раз и кладёт рядом файл-метку. Без метки забытая переменная будет стирать
данные при каждом перезапуске.

**Выкатка чужой ветки без переключения своей** — две команды, локальные
файлы не трогаются:

    git fetch origin
    git push amvera origin/<ветка>:master

Вторая берёт ветку из скачанной копии GitHub, а не из рабочей папки.
**Без свежего `fetch` уедет старая версия, и push отработает без ошибок:**
выглядит как успех, а на сайте старьё. Проверять по последней строке:
`старый..новый -> master`.

**В PowerShell нельзя `git show ... > файл`.** Значок `>` пишет файл
в UTF-16, и файл ломается. Доставать так:
`git checkout origin/<ветка> -- путь/файл`.

## 8. Как проверять, что бот работает

Не по панели хостинга и не по словам — тремя делами.

1. **Живой диалог.** Написать боту вопрос по делу и получить ответ
   за несколько секунд. Задать второй вопрос, не повторяя первый:
   если переспрашивает заново — память диалога не работает.
2. **Заявка дошла.** Назвать телефон и убедиться, что контакт пришёл
   владельцу. Это главное: бот, который красиво разговаривает и теряет
   контакты, хуже, чем его отсутствие.
3. **Строки в логе приложения.** Подключение к сообществу и результат
   отправки по каждому каналу.

Цены, которые называет бот, сверять с прайсом на сайте **до рубля**.
Человек, которому бот назвал 25 000, а страница показала 35 000, уходит
не из-за цены, а из-за расхождения.

## 9. Чего не делать

- **Не заводить второго бота-«мозг» под новый канал.** Промпт, вопросы
  и формат заявки общие; канал — только новая дверь. Три разных промпта
  разъедутся и будут отвечать по-разному.
- **Не переиспользовать токен Telegram-бота другого проекта для опроса.**
  Один токен = один слушатель, иначе `409 Conflict` и молчат оба.
  Для отправки уведомлений тот же токен использовать можно.
- **Не хранить долгую переписку без нужды.** История диалога в памяти
  процесса — осознанный размен: перезапуск её обнуляет, зато нет базы
  с чужими разговорами, которую надо защищать по 152-ФЗ.
- **Не отправлять персональные данные за границу.** Заявка с именем
  и телефоном через зарубежный сервис — трансграничная передача:
  уведомление в Роскомнадзор и правка политики. Касается и модели,
  и почтового сервера, и шлюзов WhatsApp.
