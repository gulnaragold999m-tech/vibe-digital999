## 1. Доступность и индексация

| Проверка | Норма | Почему важно |
|---|---|---|
| Главная отдаёт 200 | 200 без цепочки редиректов | Каждый лишний редирект — потеря веса и времени |
| http → https | 301, один переход | Разные протоколы = разные сайты для робота |
| www → без www (или наоборот) | 301 на выбранный вариант | Иначе две копии сайта конкурируют между собой |
| `/index.html`, `/index.php` | 301 на `/` | Дубли главной |
| Слеш в конце URL | Единообразно по всему сайту | Дубли |
| `meta robots` | `index, follow` на продвигаемых | `noindex`, забытый после разработки, — классика |
| `X-Robots-Tag` в заголовках | отсутствует или разрешающий | Запрет может стоять на уровне сервера |
| Страницы в поиске | близко к числу полезных страниц | Разрыв = проблемы с индексацией |
| Ошибки 404 внутри сайта | нет | Битые ссылки тратят краулинговый бюджет |
| Страница 404 | отдаёт код 404, а не 200 | «Мягкая 404» плодит мусор в индексе |
| Контент виден без JS | да | Робот может не дождаться рендера. Проверка: посмотреть исходный HTML |

## 2. Мета-теги и заголовки

| Проверка | Норма |
|---|---|
| `<title>` | 40–70 символов, уникальный на каждой странице, главный ключ ближе к началу |
| `<meta description>` | 120–200 символов, уникальный, с призывом и выгодой |
| `<h1>` | ровно один на странице, содержит основной коммерческий ключ |
| `h2`–`h6` | по иерархии, без пропусков уровней, без оформления текста заголовками |
| `canonical` | абсолютный URL, указывает сам на себя |
| `lang` у `<html>` | `ru` |
| Open Graph | `og:title`, `og:description`, `og:image`, `og:url`, `og:type` |
| `meta keywords` | не влияет ни на что; не вредит, но и не помогает |

**Про H1 отдельно.** Самая частая и самая дорогая ошибка — брендовый или креативный H1 без коммерческого ключа. «Мы создаём эмоции», «Вайбкодинг», «Ваш надёжный партнёр» — по этим фразам никто ничего не ищет. Ключ должен быть в H1, слоган — в подзаголовке под ним. Правка на пять минут, эффект — принципиальный.

## 3. Структура сайта и URL

- **Отдельная страница на каждый коммерческий интент.** Это главный пункт всего аудита. Если бизнес продаёт шесть услуг, а сайт одностраничный — нужно шесть страниц. Одна страница физически не может быть релевантной шести разным запросам.
- **ЧПУ:** латиница, строчные буквы, разделитель — дефис, не подчёркивание. `/uslugi/telegram-bot/` вместо `/page?id=17`.
- **Вложенность:** любая страница в 3 клика от главной.
- **Хлебные крошки:** и визуальные, и в разметке `BreadcrumbList`.
- **Внутренняя перелинковка:** услуга ↔ кейс, блог → услуга. Страницы без входящих внутренних ссылок («сироты») индексируются плохо.
- **Пагинация:** `rel="next"/"prev"` или canonical на первую страницу.

Ориентир по объёму: сайт из 30 страниц в конкурентной нише почти не имеет шансов. Точки роста, когда ассортимент ограничен:

- **Блог:** инструкции, гайды, глоссарий терминов (по странице на термин — каждая ловит НЧ-запросы)
- **Кейсы:** детальный разбор выполненных работ. Для услуг — самый эффективный тип страниц
- **Авторские колонки:** тексты от имени конкретного эксперта. Алгоритмы ценят уникальное авторское мнение
- **Дробление категорий** и рост числа карточек — для магазинов

## 4. Микроразметка (Schema.org, JSON-LD)

Самая дешёвая победа в аудите: контент уже есть, нужно только описать его для робота.

| Тип | Где применять |
|---|---|
| `Organization` / `LocalBusiness` / `ProfessionalService` | Главная. Название, адрес, телефон, `areaServed`, `sameAs` на соцсети |
| `WebSite` | Главная |
| `Service` + `Offer` | Страницы услуг, с ценой |
| `Product` + `Offer` + `AggregateRating` | Карточки товаров |
| `FAQPage` | Любая страница с блоком вопрос-ответ |
| `BreadcrumbList` | Все внутренние страницы |
| `Article` | Блог, с автором и датой |
| `Review` / `AggregateRating` | Отзывы |

Правила: тексты в разметке должны **дословно совпадать** с видимыми на странице, иначе это нарушение. Надёжнее всего собирать разметку программно из самой разметки страницы, а не перепечатывать руками.

Проверка: Яндекс.Вебмастер → Инструменты → Валидатор микроразметки; Google Rich Results Test.

## 5. Контент

- **Объём:** коммерческая посадочная — от 2000 знаков осмысленного текста. Меньше — робот считает страницу пустой.
- **Уникальность:** не копировать конкурентов. Массовая генерация однотипных текстов нейросетью тоже плохо: тексты уникальны относительно интернета, но неуникальны друг относительно друга, и это ловится.
- **Вхождение ключей:** в title, H1, первый абзац, один-два подзаголовка. Без переспама — читаемость важнее плотности.
- **Ответ на интент:** страница должна закрывать вопрос лучше, чем первая тройка выдачи. Посмотри, что у них есть, а у клиента нет: цены, сроки, условия, FAQ, калькулятор, фото работ.
- **Цены.** Отсутствие цен — коммерческий фактор с большим весом. Хотя бы «от».
- **Свежесть:** дата обновления на статьях, живой блог.

## 6. Изображения и медиа

- `alt` у всех содержательных изображений: что изображено + ключ, если уместен. У декоративных — `alt=""`.
- Осмысленные имена файлов латиницей.
- Современные форматы: WebP/AVIF с fallback.
- `loading="lazy"` для всего ниже первого экрана.
- Явные `width` и `height` — иначе вёрстка прыгает при загрузке (это метрика CLS).
- Favicon и apple-touch-icon: favicon показывается рядом со сниппетом в Яндексе.

## 7. Скорость и технические файлы

| Что | Норма |
|---|---|
| Вес страницы | до 1 МБ, идеально до 300 КБ |
| TTFB | до 200 мс |
| PageSpeed мобильный | 70+, зелёная зона 90+ |
| Core Web Vitals | LCP < 2.5 с, CLS < 0.1, INP < 200 мс |
| Сжатие | gzip или brotli включены |
| Кэширование статики | заголовки `Cache-Control` |
| HTTP/2 | включён |

**robots.txt:** доступен по `/robots.txt`, отдаёт 200, содержит `Sitemap:`. Не закрывает лишнего — забытый `Disallow: /` после разработки убивает сайт целиком. Директиву `Host:` Яндекс не учитывает с 2018 года: главное зеркало определяется 301-редиректом, требовать её в отчёте не надо.

**GET-параметры и дубли.** Метки (`utm_*`, `yclid`, `gclid`), фильтры и сортировки дают адреса вида `/?utm_source=vk`. Содержимое то же, но робот считает их отдельными страницами: дубли конкурируют между собой в выдаче, а обходы уходят на копии вместо новых страниц. Два способа закрыть: **Вебмастер → Индексирование → Настройка GET-параметров** (там же список параметров, которые робот уже нашёл на сайте) или директива `Clean-param` в robots.txt. При расхождении между ними побеждает правило, которое запрещает индексировать URL с параметром. Значимые параметры — те, что меняют содержимое страницы, — трогать нельзя, иначе из поиска выпадут нужные страницы.

**sitemap.xml:** отдаётся с `Content-Type: application/xml` или `text/xml`, кодировка UTF-8 **без BOM**, все URL в нём отвечают 200 и не закрыты от индексации. Несуществующие URL в карте дают ошибки в Вебмастере — не добавляй страницы «на будущее».

## 8. Мобильная версия

- Адаптивность без горизонтальной прокрутки.
- Кликабельные элементы от 44×44 px.
- Читаемый шрифт без зума, от 16 px.
- Телефон — ссылкой `tel:`.
- Контент на мобильной не урезан относительно десктопной: индексация идёт по мобильной версии.

## 9. Аналитика и панели

- **Яндекс.Метрика** с включённым **Вебвизором** — записи экрана посетителей. Показывает, где человек застревает и почему не отправил заявку. Для понимания поведения полезнее любой аналитики.
- **Цели** в Метрике: отправка формы, клик по телефону, переход в мессенджер. Без целей нельзя оценить, работает ли SEO.
- **Яндекс.Вебмастер:** сайт добавлен, права подтверждены, sitemap загружен, регион задан. Способов подтверждения четыре: мета-тег, файл в корне, DNS-запись и тег в менеджере тегов (Яндекс Тег Менеджер или GTM). Последний в коде страницы не виден — отсутствие мета-тега само по себе не значит, что панели нет.
- **Google Search Console:** то же самое.
- После правок — «Переобход страниц» в Вебмастере.

## 10. Коммерческие факторы и доверие

Для сайтов услуг и магазинов эти факторы влияют на ранжирование напрямую:

- Цены или вилка цен
- Телефон в шапке, кликабельный
- Несколько каналов связи: телефон, мессенджеры, форма
- Реквизиты: юрлицо или ИП, ИНН, адрес
- Договор, гарантии, условия возврата
- Реальные кейсы с фото и деталями
- Отзывы, желательно с привязкой к внешним площадкам
- Люди: имена, фото, роли. Обезличенный сайт вызывает меньше доверия и у людей, и у алгоритмов
- Политика конфиденциальности и чекбокс согласия в формах — юридически обязательны

## 11. Внешние сигналы

- **Карты и справочники:** Яндекс Бизнес, 2ГИС, Google Карты. Для локального бизнеса — самый быстрый источник доверия и переходов.
- **Контент-площадки:** экспертные статьи на vc.ru, Дзен со ссылкой на сайт.
- **Ссылки:** для Google остаются весомым фактором. Схема органичного роста — 5–10 качественных вечных ссылок в статьях в первый месяц плюс 15–30 крауд-упоминаний на форумах и сервисах отзывов. Площадки проверять на траст и баны заранее. Резкий ссылочный взрыв выглядит неестественно.
- **PR + SEO:** упоминания в СМИ дают брендовый трафик и доверие.
- **Реклама:** Директ, VK Ads, Telegram Ads подпитывают сайт трафиком, пока органика не набрала обороты. Поведенческие факторы от этого тоже растут.
