# SEO-аудит и продвижение (рунет)

Этот навык нужен, чтобы аудит получался **действием, а не списком претензий**. Разница принципиальная: список из сорока замечаний парализует, а три приоритетные задачи с понятным эффектом — двигают. Клиент платит не за перечень ошибок, а за понимание, что делать в понедельник утром.

## Главное правило приоритизации

Порядок работ почти всегда один и тот же, и он важнее полноты проверки:

1. **Структура** — есть ли вообще страницы, на которые можно посадить запросы
2. **Техника** — индексируется ли то, что есть
3. **Контент и семантика** — отвечает ли страница на запрос лучше конкурентов
4. **Внешние сигналы** — карты, площадки, ссылки, реклама

Пункт 1 почти всегда недооценивают. Одностраничник с идеальной техничкой физически не может ранжироваться по десяти разным коммерческим запросам: это десять разных интентов, им нужны десять посадочных. Если сайт — лендинг, а клиент хочет трафик по услугам, начинать нужно со структуры, и всё остальное вторично. Об этом стоит сказать прямо в первом же абзаце отчёта, иначе клиент неделю будет двигать мета-теги.

## Процесс аудита

### Шаг 0. Перечитать, где мы сами провалились

Перед аудитом нового клиента открой `references/nash-opyt.md`. Там восемь
наших ошибок с датами и ценой каждой — и порядок проверок, собранный
из них. Первые четыре пункта делаются ДО семантики и до техники, потому
что каждый из них уже один раз обесценил всю остальную работу.

Самый дорогой урок одной строкой: **реклама на сайт, с которого нельзя
связаться, отработает бюджет полностью и не даст ни одной заявки.**
У нас это стоило 8 000 ₽ за неделю, а потом ещё 37 целевых действий
и ноль заявок вторым заходом.

### Шаг 1. Автоматическая проверка

Запусти скрипт — он снимает технические факты за секунды и не ошибается там, где ошибается глаз:

```bash
node scripts/audit.mjs https://example.ru
node scripts/audit.mjs https://example.ru --json          # машинный вывод
node scripts/audit.mjs https://example.ru -o report.md    # сразу в файл
```

Скрипт проверяет HTTP и редиректы, мета-теги, заголовки, микроразметку, robots.txt, sitemap.xml, счётчики, изображения, вес и скорость ответа, объём текста. Он не требует зависимостей — только Node 18+.

Важно: скрипт видит **исходный HTML с сервера**. Если сайт рендерит контент на JavaScript, скрипт покажет пустую страницу — и это само по себе диагноз, потому что робот Яндекса видит примерно то же самое. Проверь это отдельно и вынеси в отчёт как критический пункт.

### Шаг 2. Ручная проверка того, что скрипт не видит

Скрипт не оценивает смысл. Открой сайт и посмотри глазами:

- **Структура и интенты.** Выпиши услуги/товары, которые продаёт бизнес. На каждую есть отдельный URL? Если нет — это пункт №1 отчёта.
- **Соответствие H1 и title коммерческому спросу.** Частая ошибка — брендовые и «креативные» формулировки в H1 («Вайбкодинг», «Мы создаём эмоции»). Их почти не ищут. Ключ должен быть в H1, а красивая фраза — в подзаголовке.
- **Гео.** Если бизнес локальный, города должны быть в тексте, а не только в реквизитах футера.
- **Доверие (E-E-A-T).** Реквизиты, договор, живые кейсы, имена людей, фото. Для услуг это влияет на ранжирование сильнее, чем кажется.
- **Конверсия.** Форма выше первого экрана? Телефон кликабельный? Заявка доходит? Трафик без заявок — это не SEO-победа.

### Шаг 3. Проверка индексации

Это делается только в панелях, скриптом не заменить:

- Яндекс.Вебмастер → Индексирование → Страницы в поиске. Сколько страниц в индексе против сколько на сайте.
- Вебмастер → Диагностика. Критичные ошибки разбираем первыми.
- Google Search Console → Индексирование страниц.
- Быстрая прикидка без доступов: запрос `site:example.ru` в Яндексе и Google.

Если сайт новый — доступов может не быть вообще. Тогда первый пункт плана: завести Вебмастер и Search Console, это займёт полчаса.

### Шаг 4. Семантика

Не собирай ядро «на глаз». Порядок и инструменты — в `references/semantics.md`. Ключевая мысль: новому сайту нужны **низкочастотные запросы**, потому что через них приходят первые поведенческие факторы, а уже за ними — рост по средне- и высокочастотным.

### Шаг 5. Отчёт

Структура и тон — в `references/report-template.md`. Отчёт должен отвечать на три вопроса: что сломано, что это стоит бизнесу, что делать первым.

## Как писать отчёт

**Приоритеты, а не нумерация подряд.** Три уровня: критично (блокирует рост), важно (заметный эффект), потом (мелочи). Внутри уровня — по убыванию эффекта.

**Каждый пункт объясняй через деньги или клиентов.** Не «отсутствует микроразметка FAQPage», а «шесть готовых вопросов на сайте могут занять в выдаче втрое больше места, чем строчка конкурента — сейчас эта возможность не используется».

**Отмечай, что уже сделано хорошо.** Это не вежливость: если не написать, клиент в следующий заход это сломает. И аудит без единого плюса читается как продажа услуг через страх.

**Не обещай сроков, которых не бывает.** Реальные цифры — в `references/benchmarks.md`. Обещание «топ за месяц» стоит дороже, чем кажется: через месяц придётся объясняться.

**Проверяй findings до того, как отдать.** Инструменты врут. Особенно легко ошибиться, читая сайт через конвертеры в markdown: они теряют атрибуты и показывают несуществующие проблемы. Если пишешь «нет `lang`» или «пустые ссылки» — сначала посмотри исходный HTML. Ложный пункт в аудите обесценивает остальные тридцать.

## Когда задача — не аудит, а новый сайт

Тогда SEO закладывается на этапе сборки, и переделывать не приходится. Чек-лист запуска — в `references/new-site.md`. Коротко: структура URL под интенты с самого начала, ЧПУ на латинице через дефис, уникальные title/description на каждую страницу, один H1, микроразметка, robots.txt и sitemap.xml, счётчик с вебвизором, панели вебмастеров в день запуска.

Справочники выше — операционные, заточены под рунет: Яндекс, Вебмастер, Метрика, Wordstat, Яндекс Бизнес, 2ГИС. По ним делается работа.

## Глубокая база: `references/deep/`

Отдельно лежит большая теоретическая база по SEO — конспекты профильных книг и подробные методички по направлениям. Она **дополняет**, а не заменяет справочники выше: написана в основном под Google, поэтому терминология и инструменты там западные (Search Console, Google Business Profile, Core Web Vitals, editorial link building). Общие принципы — intent, E-E-A-T, topic clusters, работа с сущностями — применимы и в Яндексе.

Читай оттуда, когда задача глубже стандартного аудита:

| Файл в `deep/skills/` | Когда открывать |
|---|---|
| `skill_technical_seo_audit.md` | Сложная техничка: crawl budget, логи сервера, Core Web Vitals |
| `skill_keyword_research.md` | Большое ядро, анализ intent, keyword gaps |
| `skill_content_strategy.md` | Topic clusters, контент-план на квартал, E-E-A-T |
| `skill_on_page_optimization.md` | Глубокая оптимизация конкретных страниц |
| `skill_competitor_analysis.md` | Разбор конкурентов, поиск пробелов |
| `skill_link_building.md` | Внешние ссылки, аутрич |
| `skill_local_seo.md` | Локальный бизнес (западная модель — сверяй с `geo-local.md`) |
| `skill_ecommerce_seo.md` | Интернет-магазины: категории, фильтры, карточки |
| `skill_entity_seo.md` | Сущности, Knowledge Graph, продвинутая микроразметка |
| `skill_seo_strategy.md` | Стратегия и роадмап на длинный проект |

В `deep/knowledge/` — конспекты книг и руководств, на которые ссылаются эти файлы. Открывай их только если нужен первоисточник: они объёмные, и для большинства задач достаточно файла навыка.

Правило приоритета при расхождении: **для рунета побеждают справочники верхнего уровня**. Например, `deep` советует Google Business Profile — для российского клиента это Яндекс Бизнес и 2ГИС, а Google Карты вторичны.

## Скрипт

`scripts/audit.mjs` — автопроверка технической части. Node 18+, без зависимостей.
Вывод: markdown-отчёт с баллом и разбивкой на критично/важно/потом, либо JSON через `--json`.
