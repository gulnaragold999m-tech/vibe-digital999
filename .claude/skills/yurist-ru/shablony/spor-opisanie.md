# Описание спора — с чего начинается разбор

Спорная ситуация описывается **файлом**, а не пересказывается в чате.
Причина простая: беседа кончится, а файл останется, и следующий разбор
не начнётся с нуля. Файл кладётся в репозиторий проекта:
`spory/<дата>-<клиент>.md`.

Пока эти поля не заполнены, разбирать нечего: без дат и сумм любой
юридический вывод — гадание.

---

```
# Спор: <клиент>, <дата>

## Что произошло
Одной фразой, без эмоций.

## Даты — по порядку
- <дата> договор подписан / не подписан
- <дата> получена предоплата <сумма>
- <дата> переданы материалы от клиента / не переданы
- <дата> сдана работа, отправлен акт
- <дата> клиент заявил <что именно>

## Документы, которые есть на руках
- [ ] Договор подписанный
- [ ] Приложение № 1 (техзадание)
- [ ] Счёт и подтверждение оплаты
- [ ] Переписка (где: почта, ВК, Telegram)
- [ ] Акт, отправлен <дата>, ответ <есть/нет>

## Деньги
- Сумма договора:
- Получено:
- Спорная сумма:

## Что сделано по факту
Ссылки на страницы, макеты, коммиты, промежуточные версии.

## Чего требует клиент
Дословно, его словами.

## Чего хотим мы
Одной фразой: закрыть миром / получить остаток / вернуть часть и разойтись.
```

---

## Дальше

Заполненный файл разбирается по пяти шагам из `SKILL.md`. Результат —
короткий вывод владелице и готовый текст письма клиенту.

**Пустое поле — это не мелочь.** «Договор подписанный — нет» меняет
весь разбор: позиция становится слабее, и говорить об этом надо сразу,
а не после того, как отправлено уверенное письмо.
