## Как работать с Гульнарой

Она не программист и не должна им становиться. Все команды выполняет в
командной строке Windows (**PowerShell**, синяя строка `PS C:\...>`), копируя
их отсюда. Проект у неё лежит локально, папку уточнить у неё же.

1. **Один шаг за раз.** Ровно одна команда или одно действие. Ждём результат
   и только потом даём следующий шаг.
2. **Никакой теории.** Не объясняем, как устроен git. Говорим, что вставить
   и что должно получиться на экране.
3. **Команды — готовыми строками** целиком. Не писать пути со стрелками
   вроде «Настройки → Фильтры»: она вставит это в адресную строку и получит
   ошибку. Так уже было. Давать прямые адреса ссылками.
4. **В рамку — только то, что нужно вставить.** Всё, что оформлено как код,
   она копирует и выполняет. Логи, тексты ошибок и примеры ответов бота в
   рамку не кладём, пишем обычным текстом. 10.08.2026 строчка из лога была
   показана в рамке и уехала в PowerShell как команда.
5. **Говорить, ГДЕ выполнять, до того как сказать ЧТО.** «В чёрном окне
   вставь…», «в браузере открой…» — первым словом. Иначе текст для сайта
   уходит в командную строку.
6. **Правки в файлах делаем мы**, в репозитории. Ей — команда скачать
   готовое и указание, куда загрузить.
7. **После каждой правки — как проверить.** Что открыть, что должно быть на
   экране, по какому слову понять, что версия новая.
8. **Не спрашивать её про устройство проекта.** Если чего-то не знаешь —
   посмотри в коде или дай ей одну команду, которая это покажет. Вопрос
   «куда пушить?» она переадресует другому чату, и работа встанет.

## Как выкатывается сайт

Хостинг — Amvera, окружение Node (см. `amvera.yaml`). Обновление идёт
через git: у Гульнары в локальной папке заведён отдельный remote на Amvera,
и выкатка — это push в него.

Порядок ровно такой, оба шага обязательны:

```
git fetch origin <ветка>
git push -f amvera origin/<ветка>:master
```

**Сначала `fetch`, потом `push`.** В команде push используется
`origin/<ветка>` — это КОПИЯ ветки, лежащая у неё на компьютере, а не то,
что на GitHub. Без свежего `fetch` на сайт уезжает старая версия, причём
push отрабатывает без единой ошибки и выглядит успешным. В соседнем проекте
10.08.2026 так выкатили версию пятидневной давности.

Проверять по последней строке push: слева старый хэш, справа тот, который
ждём. Совпал — выкатилось нужное.

`<ветка>` — та, в которой работает текущий чат. У каждого чата она своя,
вида `claude/что-то-там`. Узнать свою: `git branch --show-current`.

**Имя remote для этого проекта надо подтвердить.** В соседнем проекте
granat-kmv он называется `amvera`. Здесь, скорее всего, так же, но проверить
одной командой у Гульнары в её папке: `git remote -v`. Как подтвердится —
вписать сюда точное имя и убрать этот абзац.

`docs/04-DEPLOY-AMVERA.md` описывает ПЕРВИЧНУЮ настройку проекта на Amvera —
создание, переменные окружения, архив. Для обычного обновления нужен порядок
выше, а не он.

### Ловушки, на которых уже спотыкались

- **Переменные окружения Amvera читает только при старте.** Завёл
  переменную — нажми перезапуск, иначе получишь отказ на ровном месте.
- **В PowerShell нельзя `git show ... > файл.js`.** Перенаправление `>`
  пишет файл в UTF-16, и он ломается. Доставать файлы из ветки только так:
  `git checkout origin/<ветка> -- файл1.js файл2.js` — git пишет сам, без
  участия оболочки, и берёт несколько файлов за раз.
- **На Amvera не работает IPv6.** Всё, что ходит наружу, обязано ходить по
  IPv4, иначе соединение висит до таймаута и выглядит как «сервис не
  отвечает». В Node лечится строкой `dns.setDefaultResultOrder('ipv4first')`
  в самом начале `server.js`. Подробности и другие грабли по ботам —
  `docs/12-JARVIS-TELEGRAM-VK.md`.

## Стек
- HTML5 + Tailwind CSS.
- Vanilla JS для анимаций (Canvas для частиц).
- Node.js + Express — отдаёт статику и принимает заявки.
- Хостинг: Amvera. Домен: `vibe-digital999.ru`.

Не подключать React, сборщики и лишние зависимости, пока задача этого прямо не требует.

## Правила кода
- Mobile-first. Сначала телефон, потом десктоп.
- Стили — только Tailwind-классы. Никаких `style="..."` в разметке.
- Семантика: `header`, `main`, `section`, `footer`, `form`, `button`, `label`.
- У картинок — `alt` и `loading="lazy"`.
- Формы валидируются на клиенте до отправки.
- Все интерактивные элементы доступны с клавиатуры, у них видимый `focus`.
- Уважать `prefers-reduced-motion`: при включённой настройке анимации выключаются.

## Правила текста
- Пиши коротко и по делу.
- Не обещай того, чего нет.
- Никакой воды и красивых пустых фраз.
- Если термин может быть непонятен клиенту — объясни его одним предложением.

## Проверка перед финалом
- Логика блоков не сломана.
- На iPhone ничего не разъезжается.
- Есть один главный CTA.
- Форма отправляется и даёт понятный ответ.
- Проставлены `alt`, `label`, `aria`, `focus`.
- Страница не тормозит на слабом телефоне.
