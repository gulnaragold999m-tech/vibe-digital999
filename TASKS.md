### Как код попадает на сайт

Amvera тянет из **своего** git, а не из GitHub:
`https://git.amvera.ru/granatgold999/vibe-digital`, ветка `master`.
Доставка одной командой, локальную папку она не трогает:

```
git fetch origin
git push amvera origin/<ветка>:master
```

Amvera замечает изменения сама и пересобирает, 1–3 минуты.

### 0. Включить определение региона — один шаг

Определение города по IP написано и работает, но выключено: нужен
бесплатный ключ. Пока ключа нет, сайт работает как раньше — просто без

- [x] Регистрация на `dadata.ru`, бесплатный тариф — 10 000 запросов в сутки.
- [x] `DADATA_TOKEN` добавлен в переменные окружения Amvera.
- [x] Исправлено определение адреса за прокси: первая версия брала первую
      запись из `X-Forwarded-For`, и на Amvera это давало «локальный адрес»
      каждому живому человеку. Теперь перебираются все известные заголовки
      и берётся первый не внутренний адрес, плюс `app.set('trust proxy')`.
- [x] Проверено на живом сайте: **не работает, и не по нашей вине.**
      В журнале Amvera:

      ```
      x-forwarded-for[0]: 10.*.*.* — внутренний, отброшен
      x-real-ip:          10.*.*.* — внутренний, отброшен
      req.ip:             10.*.*.* — внутренний, отброшен
      ```

      Прокси Amvera затирает адрес посетителя своим внутренним вместо
      того, чтобы дописать его в цепочку X-Forwarded-For. Настоящий адрес
      до приложения не доходит, и определить регион по нему невозможно
      никаким кодом на нашей стороне.

      Код при этом рабочий и остаётся в проекте: заработает сам, без
      единой правки, как только заголовок начнёт приходить. Сайт от этого
      не страдает — подсказки «похоже, вы из Краснодарского края» просто
      нет, а выбор региона руками на главной работает как работал.

- [ ] **Написать в поддержку Amvera** (чат поддержки в левом меню кабинета):
      «Приложение vibe-digital за вашим прокси получает в X-Forwarded-For
      и X-Real-IP внутренний адрес 10.x.x.x вместо адреса посетителя.
      Можно ли включить передачу настоящего IP клиента?»
      Это обычная настройка ingress, у большинства хостингов она есть.

- [ ] Если поддержка не сможет — запасной путь: спрашивать DaData прямо
      из браузера. Тогда сервис видит адрес посетителя сам, и прокси
      не мешает. Цена вопроса: ключ окажется в коде страницы, поэтому
      его придётся ограничить доменом в кабинете DaData
      («Настройки» → ограничение по домену). Данные всё так же остаются
      в России. Делать только после ответа поддержки — сначала простой
      путь, потом сложный.

Почему DaData, а не зарубежный сервис: IP-адрес посетителя — персональные
данные, и отправлять его за границу нельзя без отдельного основания.
DaData российская, данные остаются в России.
